# Приёмка рабочего места координатора

Для демонстрации запустите приложение по [инструкции запуска](../README.md). Откройте «Управление стендом» и выберите нужный набор. Все действия относятся к локальному стенду. Профиль координатора переключается в «Моя смена».

| Сценарий | Как проверить | Ожидаемый результат |
|---|---|---|
| Исходный кейс | Открыть «Кейс МТС» с исходным JSON | В четырёх группах 0 критических, 2 на координаторах, 1 активный высокого приоритета и 5 на исследовании. У карточки без срока указан статус «Срок не указан». |
| Обзор INC и быстрый просмотр | Открыть критическую карточку с истёкшим сроком и без принятой задачи. Из боковой панели перейти в полный обзор при 1440 и 390 px. | Срок отображается в часах и минутах. Отдельно видны группа ITSM, исполнитель и координатор смены. Если встреча ещё не привязана, показано «Ссылка пока не получена». |
| Новая авария | Повысить приоритет активного INC до 4 в файле, изменить команду и срок | Без перезагрузки появляются номер INC, продукт, срок и сигнал. Тот же снимок можно применить повторно. Ошибка в файле оставляет доступной последнюю корректную версию. |
| Серия критов | Одним изменением добавить два крита, дождаться их показа и добавить третий. Нажать «Увидел» | Смена подтверждает только два показанных события. Третий остаётся в очереди. Открыть его вручную можно сразу. Автоматический показ ждёт 30 секунд. |
| Восстановление и история | Перевести активный INC в Resolved, затем в Research. Оставить группу координаторов. В «Хронологии» открыть изменение поля и «Сравнить версии карточки». | Видны восстановление, пересечение двух очередей, прежнее и новое значения. Время получения снимка и доступное время источника подписаны. Из строки «Журнала смены» открывается то же событие. |
| Параллельные назначения | Создать две персональные задачи. Для принятой задачи согласовать команду в «Кому передать». В «Моей смене» проверить подставленную команду, исправить её и передать INC. | Квитанция показывает сохранённую группу. После передачи дежурный может принять следующий INC. При подключённой ITSM редактор показывает результат её ответа. |
| Персональный таймер | На критическом INC нажать «Увидел», закрыть вкладки на минуту и открыть «Моя смена» | Следующий свободный координатор получает свою минуту. Старая попытка принятия отклоняется. При отсутствии свободного дежурного задача ждёт в очереди. |
| Комната и передача смены | В обзоре оплаты открыть «Демовстреча». В «Управлении стендом» выбрать этот INC, открыть управление демовстречей и отметить приглашение, вход, выход и завершение. В обзоре сохранить следующий шаг через «Заметки и действия», затем открыть «Передача смены». | Лента «Комната» в хронологии показывает события именно этой встречи. По рабочей ссылке доступны участники и фрагменты расшифровки. В личном рабочем месте сводка содержит действие и ответственного. |
| Гипотеза агента | Открыть или запустить разбор оплаты. Через «Управление стендом» → «Условия разбора ИИ» сменить профиль с БД на обработчики. В разборе нажать «Повторить разбор». Отдельно проверить недоступность телеметрии и модели. | Гипотеза, адресат и следующая проверка учитывают измерения. Для одной записи ITSM дежурный видит, какие данные запросить. Сохранённый запуск и его исходные записи доступны по постоянным ссылкам. Повторное открытие отчёта не создаёт новый запуск. |
| Сравнение мер | В последнем разборе оплаты открыть «Проверить на стенде» и выполнить демопрогон с одной нагрузкой для трёх вариантов. | Локальный сервер принимает уникальные заказы и сохраняет число подтверждений в срок. Отчёт показывает прогноз, результат и влияние ограничения фоновой сверки. |
| Похожие инциденты | В «Управлении стендом» запустить «Сценарий Wi-Fi · Ростов». В «Похожих случаях» сверить случай в Москве и подтвердить связь. В настройках стенда задать доступность дежурных, в обзоре открыть «Кому передать». | Основания видны до подтверждения. Подтверждённая связь есть в обеих карточках. В рекомендации видны состав, ожидание и решение координатора. |
| Доставка | В «Управлении стендом» включить ошибку SMS. Из карточки нажать «Запросить статус» и отправить сообщение по девяти каналам. Снять ошибку на стенде. В «Моей смене» → «Уведомления» повторить неудачную доставку. | Доступны квитанции по каналам. После повтора число попыток растёт только у SMS. |
| Ротация при неизменном итоге | Подать первый снимок с 479 активными критическими INC. За одну минуту перевести 300 из них в Resolved и добавить 300 новых активных критических INC | В оповещении, на общем экране и в очередях видно 479 сейчас, 300 добавилось и 300 выбыло. До обновления таблицы координатор продолжает читать прежние строки. Журнал минуты содержит 600 переходов с номерами INC. |
| Навигация между очередями | В «Очередях» открыть страницу 2 критических и страницу 3 высокого приоритета. Перейти к карточке и обратно, затем нажать название другой очереди слева | На странице четыре секции. Меняется позиция прокрутки. У каждой таблицы сохраняются собственные фильтры, размер и номер страницы. |
| Большая смена | Открыть набор на 3600 INC, найти номер, сохранить представление, открыть быстрый просмотр и перейти в карточку | Фильтр, пагинация и постоянная ссылка позволяют работать с конкретным INC. Сохранённое представление доступно после перезагрузки. |

Команда `npm test` проверяет правила очереди, журнал, обработку JSON и сохранение данных в SQLite. Команда `npm run test:browser` проверяет действия через интерфейс, включая изменение файла на работающем сервере, тайм-аут с закрытым браузером, восстановление источника и открытие сохранённого наблюдения. Браузерные проверки создают временную базу для каждого сценария.

В стандартном прогоне ITSM, Emergency Room, МТС Линк, агент и каналы связи используют моковые данные. Доступна и [сквозная проверка с Ollama и отдельной ITSM](outage-operations.md). Файловый ввод, HTTP-запросы, таймер, квитанции и сохранение состояния работают локально. Такое разделение позволяет воспроизвести прогон без корпоративных учётных записей.
