# Приёмка рабочего места координатора

Для демонстрации запустите приложение по [инструкции запуска](../README.md). Откройте «Моя смена» → «Источник данных» и выберите нужный набор. Все действия относятся к локальному стенду. Профиль координатора переключается в «Моя смена».

| Сценарий | Как проверить | Ожидаемый результат |
|---|---|---|
| Исходный кейс | Открыть «Кейс МТС» с исходным JSON | В четырёх группах 0 критических, 2 на координаторах, 1 активный высокого приоритета и 5 на исследовании. У карточки без срока указан статус «Срок не указан». |
| Новая авария | Повысить приоритет активного INC до 4 в файле, изменить команду и срок | Без перезагрузки появляются номер INC, продукт, срок и сигнал. Тот же снимок можно применить повторно. Ошибка в файле оставляет доступной последнюю корректную версию. |
| Серия критов | Одним изменением добавить два крита, дождаться их показа и добавить третий. Нажать «Увидел» | Смена подтверждает только два показанных события. Третий остаётся в очереди. Открыть его вручную можно сразу. Автоматический показ ждёт 30 секунд. |
| Восстановление и история | Перевести активный INC в Resolved, затем в Research. Оставить группу координаторов. Открыть историю и сравнить версии | Видно восстановление, пересечение двух групп и прежние значения полей. Время источника и время наблюдения подписаны. Переход в мок-ITSM открывает тот же номер. |
| Параллельные назначения | Создать несколько задач для координаторов. Принять одну и передать группе решения | У дежурного одна текущая задача. Завершение внутренней передачи освобождает дежурного для следующей. |
| Персональный таймер | На критическом INC нажать «Увидел», закрыть вкладки на минуту и открыть «Моя смена» | Следующий свободный координатор получает свою минуту. Старая попытка принятия отклоняется. При отсутствии свободного дежурного задача ждёт в очереди. |
| Комната и передача смены | На карточке платежей открыть «Аварийная комната». Проверить приглашение, вход, выход. В «Работе смены» сохранить следующий шаг с ответственным. Завершить встречу | Для каждого участника видны доставка и участие. Сводка содержит действие и ответственного. Кнопка у времени открывает исходный фрагмент. |
| Гипотеза агента | На карточке платежей запустить разбор. Изменить профиль с БД на обработчики и повторить. Отключить телеметрию | Гипотеза и следующая проверка меняются с измерениями. При пропуске измерений показаны недостающие сведения. Сохранённые наблюдения открываются по ссылке даже после перезагрузки. |
| Сравнение мер | В том же разборе запустить прогон с одинаковой нагрузкой для трёх вариантов | Локальный сервер принимает уникальные заказы и сохраняет количество подтверждений в срок. Отчёт показывает прогноз, результат и влияние ограничения фоновой сверки. |
| Похожие инциденты | Запустить «Сценарий Wi-Fi · Ростов», сверить случай в Москве, подтвердить связь и указать доступность специалистов | Основания видны до подтверждения. Подтверждённая связь есть в обеих карточках. Рекомендация учитывает состав смены и сохраняет решение координатора. |
| Доставка | Имитировать отказ SMS, отправить сообщение по девяти каналам, восстановить SMS и повторить доставку | У каждого канала собственный статус. Счётчик попыток растёт только у SMS. |
| Большая смена | Открыть набор на 3600 INC, найти номер, сохранить представление, открыть быстрый просмотр и перейти в карточку | Фильтр, пагинация и постоянная ссылка позволяют работать с конкретным INC. Сохранённое представление доступно после перезагрузки. |

Команда `npm test` проверяет правила очереди, журнал, обработку JSON и сохранение данных в SQLite. Команда `npm run test:browser` проверяет действия через интерфейс, включая изменение файла на работающем сервере, тайм-аут с закрытым браузером, восстановление источника и открытие сохранённого наблюдения. Браузерные проверки создают временную базу для каждого сценария.

ITSM, Emergency Room, МТС Линк, агент и каналы связи используют моковые данные. Файловый ввод, HTTP-запросы, таймер, квитанции и сохранение состояния работают локально. Такое разделение позволяет воспроизвести прогон без корпоративных учётных записей.
