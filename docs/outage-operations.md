# Одна авария в двух окнах

Откройте блок «Требуют внимания» на сводке смены. На большом экране откройте тот же сервер и набор данных с параметрами `?mode=monitor&dataset=case`. Кнопка «Видеостена» включает полноэкранный режим для текущего набора. Esc возвращает к работе.

1. В 11 сервисах нарушился вход через МТС ID. Пришло 100 INC с ошибкой `AUTH_TIMEOUT`. Одновременно в хранилище остановилась резервная копия. В рабочем списке появляются две ситуации. На стене видны масштаб каждой и кто её ведёт.
2. Нажмите «Увидел». Пульт подтверждает показанные сигналы. Стена продолжает показывать «Никто не взял». В рабочем списке откройте общую аварию и нажмите «Взять в работу». На стене появится имя координатора.
3. В составе группы найдите INC, отметьте строки и нажмите «Исключить выбранные». Кнопка «Добавить INC» открывает поиск по активным карточкам. Можно изменить сразу несколько строк. Ручной выбор сохраняется при следующей загрузке карточек и при перезапуске сервера.
4. Из строки INC откройте «Изменить в ITSM». Выберите исполнителя, укажите команду и сохраните. После подтверждения ITSM эти значения появятся в карточке и истории. Группу аварии продолжает вести принявший её координатор.

## Как строится группа

Если в выгрузке есть проверяемая цепочка родителей, пульт использует её. Для остальных активных карточек он ищет общую зависимость, совпадающий код ошибки или конкретный симптом и близкое время регистрации. Для новой такой группы нужны как минимум два затронутых сервиса. Сбой отдельного сервиса с наивысшим приоритетом и возврат назначения по кругу также попадают в список внимания.

Кандидат доступен смене сразу. Сервер отправляет модели сжатые признаки всей группы. В группе видны основание и вердикт. Если модель отклонила гипотезу, ещё не принятые и не исправленные вручную INC возвращаются к самостоятельной оценке. Принятая авария и ручные решения сохраняются. Появление карточек в одно время само по себе не подтверждает общую причину.

## Подключение

Задайте пульту `MCC_GROUP_MODEL` с именем установленной модели Ollama и `MCC_OLLAMA_URL` с адресом сервера. Проверенный пример модели — `hf.co/Qwen/Qwen2.5-3B-Instruct-GGUF:Q4_K_M`. При недоступности модели пульт продолжает показывать группы по наблюдениям и повторяет запрос. Для реального HTTP-редактирования задайте `MCC_ITSM_URL` для отдельного приложения ITSM или `MCC_DASHBOARD_URL` для Spring API. В контейнере укажите адреса, доступные из его сети. [Контракт и запуск стендовой ITSM](itsm-edit.md).

## Воспроизведение в двух окнах Chromium

Для этого прогона нужны два отдельных локальных процесса и пустое состояние для каждого. В папке фронтенда создайте временный каталог.

```sh
outage_run=$(mktemp -d)
node scripts/outage-scenario.mjs "$outage_run/itsm.json"
echo '[]' > "$outage_run/incoming.json"
```

Запустите стендовую ITSM команды с исходной фикстурой `$outage_run/itsm.json`, отдельным файлом состояния и портом 5392. Затем запустите пульт на порту 5193. Для второго терминала подставьте тот же абсолютный путь в `outage_run`.

```sh
npm run build
MCC_STATE_DIR="$outage_run/desk" MCC_SOURCE_FILE="$outage_run/incoming.json" \
  MCC_ITSM_URL=http://127.0.0.1:5392 MCC_GROUP_MODEL='hf.co/Qwen/Qwen2.5-3B-Instruct-GGUF:Q4_K_M' \
  PORT=5193 npm start
```

```sh
MCC_VERIFY_FRONT=http://127.0.0.1:5193 MCC_ITSM_URL=http://127.0.0.1:5392 \
  MCC_SOURCE_FILE="$outage_run/incoming.json" MCC_VERIFY_FIXTURE="$outage_run/itsm.json" \
  node tests/outage-journey.mjs
```

Укажите в окружении учетную запись тестового координатора через `MCC_SMOKE_USERNAME` и `MCC_SMOKE_PASSWORD`, а также доверенный адрес `MCC_KEYCLOAK_URL`. Для отдельного тестового порта зарегистрируйте его точный origin и `/auth/callback` в тестовом клиенте. Обе сессии пройдут обычный вход через Keycloak.

Проверка откроет два изолированных окна Chromium, загрузит 101 карточку и дождётся ответа модели. Затем она примет аварию, исправит её состав и переназначит один INC. Последний шаг читает подтверждённые поля напрямую из отдельного процесса ITSM. Укажите `MCC_BROWSER_CHANNEL=chrome` для установленного Google Chrome. Переменная `MCC_MONITOR_SCREENSHOT` задаёт путь для снимка стены после принятия аварии.
