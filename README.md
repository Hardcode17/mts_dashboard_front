# MTS Dashboard Frontend

React + TypeScript + Vite с [Gravity UI](https://gravity-ui.com/libraries/uikit).
Рабочее место координатора MCC. Общий экран показывает критические инциденты, назначения, сроки и восстановления. Карточка объединяет историю ITSM, комнату, действия смены и разбор агента.

[Сценарии работы смены и маршрут демонстрации](docs/use-cases.md).

## Дизайн-система

- `src/theme/` — рабочая тема приложения: `mts-theme.css`, `fonts.css`,
  `mts-navigation.css` и шрифты `fonts/`. Подключается в `src/main.tsx` после
  стилей UIKit.
- `docs/design/mts-gravity/` — исходный пакет дизайна: `styles.json` и
  `styles-v2.json` для Themer, обе версии CSS-темы, шрифты, автономный
  предпросмотр `preview/index.html` и скриншоты. В сборку не попадает.

Проект использует `@gravity-ui/uikit` 8, поэтому в `src/theme/` взята
`mts-theme-v2.css` (структура токенов UIKit 7+). Вариант `mts-theme.css` для
UIKit 6 хранится в `docs/design/mts-gravity/` как справочный. Не подключайте обе
темы одновременно.

## Локальная разработка

Требуется Node.js 24 LTS и npm.

```sh
npm ci
npm run dev
```

Откройте [сводку смены](http://localhost:5173). В разделе «Источник» доступны два независимых набора.

- **Большая смена** содержит 3600 инцидентов и 14 400 исходных событий. Откройте [случай с оплатами](http://localhost:5173/incidents/INC000021940112?source=volume) и нажмите «Разобрать причину агентом». Раскройте исходную запись под выводом. В условиях проверки можно переключить узкое место с БД на обработчики и повторить анализ. Сравнение мер запускает HTTP-заказы в демомагазине.
- **Кейс МТС** читает 44 карточки из `mock/fixtures/incidents.json`. На исходном снимке в четырёх группах соответственно 0, 2, 1 и 5 карточек. Для демонстрации с собственным файлом задайте `MCC_SOURCE_FILE=/абсолютный/путь/к/файлу.json` перед запуском. Сервер проверяет файл каждую секунду, браузер опрашивает сервер каждые две секунды. При ошибке предыдущий снимок остаётся доступен.
- **Новый крит** открывает общее оповещение. «Увидел» подтверждает показанные события. Назначенный координатор отдельно принимает задачу в разделе «Моя смена». Через 60 секунд без ответа сервер ищет другого свободного дежурного. Таймер работает и при закрытых вкладках.
- **Wi-Fi в Ростове** запускается из раздела «Источник» на большой смене. В карточке подтвердите связь с прошлым случаем и задайте доступность команды. Раздел «Работа смены» сохраняет решение координатора, заметки и сводку передачи. В «Аварийной комнате» доступны приглашения, участие и деморасшифровка после завершения встречи.

Действия, доставки, история и отчёты хранятся в SQLite в `.mcc-stand/workspace.sqlite`. Для отдельной демонстрации задайте другой `MCC_STATE_DIR`. Два браузера, подключённые к одному серверу и набору, видят одну смену. Внешние каналы, ITSM, МТС Линк, источники телеметрии и модель агента работают на демонстрационных данных. Журнал фиксирует доставку внутри стенда.

### Автоматические проверки

[Сценарии приёмки и ожидаемые результаты](docs/acceptance.md).

`npm test` проверяет правила смены, обработку выгрузки и сохранение состояния после перезапуска. `npm run test:browser` собирает приложение и проходит сценарии в Chromium. На машине без Chrome для macOS и без установленного Chromium выполните `npx playwright install chromium`. Браузерный сценарий переназначения ждёт реальные 60 секунд.

```sh
npm run lint
npm run build
npm run preview
```

Исходники находятся в `src/`, статические файлы — в `public/`, результат сборки — в `dist/`.

## Деплой через Docker

Требуется запущенный Docker Engine с поддержкой Linux-контейнеров и Docker Compose.
Из папки проекта:

```sh
docker compose up -d --build
```

Приложение: http://localhost:8080. Порт можно изменить переменной `FRONTEND_PORT`
в окружении или в локальном файле `.env`, например `FRONTEND_PORT=3000`.

Node.js 24 собирает приложение и запускает HTTP-сервер на порту 3000. Он отдаёт статику, обрабатывает маршруты приложения, запросы `/api/stand/` и демонстрационные ответы официального контракта `GET /api/dashboard/users` и `PATCH /api/dashboard/incidents/{incidentId}` (KAN-12/KAN-58). Compose хранит базу в томе `mcc-stand` и подключает каталог исходной выгрузки для чтения.
Контейнер работает от непривилегированного пользователя `node`.
Для запуска сборки без Docker: `npm run build`, затем `npm start` (http://localhost:3000).

```sh
docker compose logs -f frontend
docker compose down
```

После изменения исходников снова выполните `docker compose up -d --build`.

## Автодеплой GitHub Actions

Workflow `.github/workflows/deploy.yml` запускается после push в `main`
или вручную через Actions → Deploy frontend → Run workflow (ветка `main`).
Используется runner организации Hardcode17 с метками `self-hosted`, `Linux`,
`ARM64`, `pi-web` (настроенный `raspberrypi-front`).

На runner должны быть запущены Docker Engine и установлен Docker Compose v2
с поддержкой `up --wait`. Пользователь службы runner должен иметь доступ к Docker
без `sudo`. В настройках группы runner разрешите доступ репозиторию
`Hardcode17/mts_dashboard_front`.

Workflow собирает образ непосредственно на ARM64 runner, проверяет линтер и
TypeScript, заменяет контейнер и ждёт успешного healthcheck. До успешной сборки
работающий контейнер не останавливается. Одновременные деплои выполняются по очереди.

Адрес после деплоя: `http://<IP Raspberry Pi>:8080`.
Для другого порта задайте переменную репозитория `FRONTEND_PORT` в
Settings → Secrets and variables → Actions → Variables. Порт должен быть доступен
в сетевых настройках сервера. SSH и registry secrets для этого способа не нужны.

Для ручного управления контейнером на runner используйте тот же Compose project:

```sh
docker compose -p mts-dashboard-front ps
docker compose -p mts-dashboard-front logs -f frontend
```
